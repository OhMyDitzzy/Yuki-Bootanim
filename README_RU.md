# Yuki Boot Animation

Модуль для Magisk / KernelSU / KernelSU Next / APatch, который позволяет
устанавливать пользовательскую анимацию загрузки прямо через WebUI — без
ручного `adb push`, перепаковки прошивки и создания нового ZIP-модуля при
каждой смене анимации.

Откройте страницу модуля в менеджере, выберите файл `.zip` (стандартная
Android-анимация загрузки) или `.qmg` (Samsung One UI). Модуль определит
менеджер root-доступа и подходящий способ установки, затем установит файл.

> **Примечание:** модуль рассчитан на работу с метамодулем **OverlayFS**.
> Пользователям **Magisk** может понадобиться сначала установить модуль
> [magic_overlayfs](https://github.com/agreenbhm/magic_overlayfs).

## Возможности

- **Установка через WebUI** — после первоначальной настройки терминал не нужен.
- **Автоопределение языка** — WebUI использует язык устройства. Доступны русский
  и английский переводы; для остальных языков используется английский.
  Вывод установщика и описание модуля также локализуются во время установки.
  Файлы переводов находятся в `webroot/locales/` и загружаются локально;
  после установки анимации описание обновляется с её статусом и путём.
- **Два формата анимации загрузки** — стандартный `bootanimation.zip` для
  большинства устройств и формат Samsung `.qmg` (`bootsamsung.qmg` /
  `bootsamsungloop.qmg`) для One UI. Модуль определяет нужный формат и проверяет
  файл до начала установки.
- **Автоматический выбор способа установки** — сначала модуль пытается
  перемонтировать `/system` в режиме записи. Если это невозможно (например,
  из-за активного dm-verity/AVB), используется overlay-путь модуля через
  **OverlayFS**.
- **Определение пути для разных прошивок** — анимация может находиться не только
  в `/system/media`. Модуль проверяет `/product/media`, `/product/etc/media`,
  `/oem/media`, `/system/media` и `/system/product/media`, отдавая предпочтение
  пути, где уже найден файл анимации. Если подходящий путь не подтверждён,
  это отмечается в журнале установки и описании модуля. Прошивки с путём вне
  этого списка автоматически определить не получится.
- **Автоматическое резервное копирование и восстановление** — исходный файл
  сохраняется перед заменой и восстанавливается при удалении модуля.

## Установка

1. **Только для Magisk:** установите и активируйте модуль
   [magic_overlayfs](https://github.com/agreenbhm/magic_overlayfs), затем
   перезагрузите устройство. **Для KSU / KSU Next / APatch:** установите
   метамодуль, например [Hybrid-Mount](https://github.com/Hybrid-Mount/meta-hybrid_mount)
   или [Mountify](https://github.com/backslashxx/mountify). Рекомендуется
   Hybrid-Mount.
2. Установите ZIP-модуль через менеджер Magisk, KernelSU или APatch.
3. Перезагрузите устройство, чтобы модуль определил root-менеджер, уровень API
   и путь анимации загрузки.
4. Откройте страницу модуля в менеджере и выберите файл `.zip` или `.qmg`
   через WebUI.
5. Перезагрузите устройство ещё раз, чтобы увидеть новую анимацию.

## Решение проблем

- **Файл загружен без ошибок, но анимация не изменилась.** Проверьте описание
  модуля в менеджере: там указан путь, куда установлен файл. Если использовался
  overlay-путь, убедитесь, что OverlayFS активен и настроен на подключение этого
  пути.
- **Ошибка «Direct remount to /system fails ... install a metamodule».**
  Перемонтировать `/system` в режиме записи не удалось — вероятно, активен
  dm-verity/AVB. Для overlay-установки нужен OverlayFS. Если вы используете
  Magisk, проверьте, что модуль
  [magic_overlayfs](https://github.com/agreenbhm/magic_overlayfs) установлен
  и активен, затем перезагрузите устройство и повторите попытку.
- **После установки этого модуля другие модули стали неактивны.** Такое поведение
  не ожидается. Если это произошло, сообщите об ошибке, указав root-менеджер,
  версию Android и установлен ли OverlayFS.
